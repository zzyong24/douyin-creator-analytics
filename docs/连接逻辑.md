# 连接逻辑

本文依据 `src/` 与 `launchd/` 当前实现描述运行契约。正式路径为本机持久化上下文，采集仅使用列表与导出；底层保留的 CDP 模拟测试不代表 CLI 支持接管正在使用的浏览器。

## 路径、权限与命令锁

`runtime.mjs` 的 `MODULE_DIR` 从 `import.meta.url` 推导模块根目录；`ROOT` 是 `DOUYIN_ANALYTICS_HOME` 解析后的绝对路径，未设置则等于模块根。数据库固定在 `<ROOT>/data/douyin.sqlite`，日志在 `<ROOT>/logs`，报告在 `<ROOT>/reports`；登录提示引用模块源码路径。

CLI 设置 umask 077，建立上述目录并设为 0700；发现目录为符号链接或真实路径与预期不符则拒绝。文件通常以 0600 写入。`logs/command.lock` 采用独占创建，记录 PID、随机 owner 和开始时间。只有确认 PID 已死且 inode 与内容未变才恢复旧模块锁；空锁还需 lsof 和进程列表明确证明无人使用。无法确认时返回 `COMMAND_LOCKED`，不杀进程。

`finally` 和信号清理关闭本次上下文、数据库并释放自己持有的模块锁；SIGINT / SIGTERM 对应 130 / 143。这里的模块锁恢复逻辑不适用于 Ego 的锁。

## Ego Lite 持久化登录档与锁检测

`ego.mjs` 的默认值为：

- 用户数据根：`$HOME/Library/Application Support/Citro Labs/ego lite`，可用 `EGO_USER_DATA_DIR` 覆盖。
- 可执行文件：`/Applications/ego lite.app/Contents/MacOS/ego lite`，可用 `EGO_EXECUTABLE` 覆盖。
- profile：固定 `--profile-directory=Default`，路径配置不要包含末尾的 `Default`。

启动前用 lstat 检查用户数据根的 `SingletonLock`，悬空锁链接也视为占用。再用 `ps` 检查 Ego 可执行文件或目标 `--user-data-dir`。锁存在或目标进程存在均为 `EGO_PROFILE_LOCKED`、退出 4；检查本身失败为 `EGO_PROFILE_CHECK_FAILED`、退出 1。即使怀疑是旧浏览器锁，也绝不删除。

预检通过才调用 Playwright `chromium.launchPersistentContext`，指定 Ego 自身入口、持久化用户数据根和 Default profile。无 chrome channel，不下载另一套浏览器；去掉 Playwright 的 `--use-mock-keychain` 和 `--password-store=basic` 默认参数，沿用 Ego 的 macOS Safe Storage。采集无界面，允许下载，阻止 service worker；登录为有界面。

Chromium 启动时仍可能与用户打开 Ego 发生竞态。若错误指向 SingletonLock / ProcessSingleton / profile 占用，保留退出 4；其他启动失败复查锁后返回脱敏错误，不输出可能含授权信息的 Playwright 原始日志。正常退出只关闭本次持有的 context，不另行强杀进程或自动重启 Ego。

正式 `launch()` 拒绝 `EGO_CDP_URL` 与 `ANALYTICS_ROUTE_ISOLATION`。底层 `openEgo()` 的本机 CDP 分支仅作历史兼容与离线模拟测试，不能通过设置环境变量使正式 CLI 绕过独占模式。

## 登录态与账号约束

连接类 CLI（login、probe、shape、collect、sample）及安装检查都要求非空 `DOUYIN_EXPECTED_NICKNAME`。未设置则在连接前返回 `EXPECTED_NICKNAME_REQUIRED`，退出 1 并提示设置变量；不会跳过账号核对。离线 report / import-export 不需要昵称环境变量。

采集导航 `https://creator.douyin.com/creator-micro/home`，读取 GET `/aweme/v1/creator/user/info/`。`status_code=8` 或 HTTP 401 为 `NEEDS_LOGIN`、退出 3。必须得到 `status_code=0`、昵称和稳定字符串身份标识；当前支持 `user_profile.nick_name` 与 `secret_id` 等解析结构，不能只用昵称或展示 handle 证明身份。昵称去首尾空白后必须与配置完全相等；稳定标识只取 SHA-256 指纹与 `data/account.json` 中的可选绑定比较，错号即 `ACCOUNT_MISMATCH`。

collect 在绑定不存在时可复用有效登录，但仍必须核对昵称；显式 login 成功才创建缺失的绑定记录。有旧绑定时不会自动覆盖它。多账号应隔离数据根，避免昵称相同但账号不同导致串库。

页面正文出现扫码登录提示时返回登录失效；验证码、滑块、安全验证或访问过频返回 `CAPTCHA`；403 和 429 分别返回对应错误。collect 登录失效时运行状态保存为 `needs_login`，保留退出 3，即使之前已有部分数据也不会变成 2。login 最多等待 10 分钟，人工完成登录后再次核对身份；超时退出 3。shape 仅输出键名结构，不确认身份通过。

## 路由策略与审计

`browser.mjs` 的无界面上下文安装路由，只处理本次新建页面及其弹窗；观察器也只处理这些页面。业务写路径关键词包含 publish、upload、delete、remove、edit、update、modify、create、submit、send、digg、like、follow、unfollow、reply、logout、comment、post_item、write、set_，按路径分隔边界匹配。

当前策略：

1. 非 GET / HEAD / OPTIONS、非静态资源、命中写路径关键词的请求拒绝；精确导出例外表当前为空，没有通配例外。
2. 当前没有已确认的 GET 写接口，因此不因 GET 路径包含 comment / create 等字样就拦截。若未来确认 GET 写接口，须按 host+path+method 增加有证据的精确阻止规则和测试，不能扩大为关键词封锁全部 GET。
3. script、stylesheet、image、font、media 或已识别静态后缀放行，不误伤静态文件名。
4. `douyin.com` 及其子域的子文档放行，包含登录所需的存储桥 iframe；`douyin.com.evil.test` 不受信任。
5. 主文档另有导航白名单：创作者主页、内容管理页、分析入口及 data-center 子路径。其他主文档会阻止，这与业务写接口过滤是两道独立规则。
6. 页面正常初始化、监控与只读请求可使用 POST，只要没有命中写路径关键词就放行。该策略并非“阻止全部 POST”，也不应被理解为允许 Agent 主动调用未知 POST。

POST 及被拒请求写入 `logs/allowed-post.jsonl`；字段固定为 `at/action/method/host/path`，URL 只保留 host+path，不保存 query、header、body 或 Cookie。探针 URL 去掉查询串和片段，异常消息中的 URL 与授权词值脱敏。发现工具仅记录 host+path、状态、内容类型、键名及数组长度；动态 ID 路径片段会脱敏。SQLite 的 `raw_json` 是经 sanitize 过滤的业务来源，不是请求头转储。

有界面的 login 不安装上述采集 route，以免破坏人工登录。操作者应只做登录维护，不执行平台业务写操作。

## 限流与重试

`RequestGate` 是 Promise 串行队列，只约束程序主动的 fetch、导航、只读按钮 / 搜索操作，覆盖该次操作与响应读取完成。下一次从上次完成时间起至少等待 4 秒，再加 0–1200 毫秒正抖动；状态落在 `data/throttle.json`。

浏览器页面自然请求不进队列、不等待 `response.finished()`；否则网页初始化、登录存储桥与多路资源可能互相卡住。自然响应 429 只给下一次主动请求设置冷却。

普通可重试错误最多重试 3 次，即至多 4 次尝试，按 4/8/16 秒加抖动退避；429 冷却为 120/240/480 秒加抖动，持久化给队列兑现。登录失效、验证码、错号、身份未知、403 等直接停止，不用重试绕过风控。

## 主目录与分页

管理页为 `/creator-micro/content/manage`。`collect.mjs` 先观察页面自然 GET 响应，主源固定 `/janus/douyin/creator/pc/work_list`，结构为 `aweme_list`、`total`、`max_cursor`、`has_more`。从页面正文解析“作品(N)”或等价总数，初始响应必须与页面总数一致且带请求 `max_cursor`，排除只返回置顶或其他场景子集的响应。

后续复制实际观察到的请求 URL 模板，仅更新 `max_cursor` 为响应给出的下一游标。`count` 等参数保留页面实际值，不擅自扩大页大小，不猜 scene/status、签名或令牌。游标用字符串，不能把长数字转浮点。每页按 `aweme_id` 去重，必须走到 `has_more=false`，最后去重数必须等于稳定 total 和页面数。

total 缺失 / 改变、has_more 未知、游标不前进 / 回环、分页没有新增 ID、数量超过 total、终止时数量不足都停止；循环上限 1000 页。成功获得的每条数据立即保存，后页失败仍保留先前快照。作者字段若带昵称，也必须与预期账号一致。

可选副源 `/web/api/creator/item/list` 使用同管理页已经观察到的自然响应，不为寻找它切去投稿或直播场景。仅当 total、完整分页及作品 ID 集合均与主目录一致后整体合并；范围不确认只写 warning、`merged=false`，不把主目录成功降为 partial。登录失效、验证码、错号仍立即停止。正式采集不进入详情页；plays、likes、comments、shares、favorites 为基础完整性要求，详情指标可 NULL。

## XLSX 导出与匹配

在未筛选管理页观察“作品(N) / 审核状态 / 体裁 / 发布日期”及唯一“导出数据”按钮，点击后等待一次下载。只接受已观察的 `creator.douyin.com` GET `/web/api/creator/item/list/download` 返回 200，若按钮、页面范围或下载合同变化则停止。该接口读取平台导出，不属于平台业务写操作。保存到 `data/exports/run-<id>-<timestamp>.xlsx`，并保存 manifest、SHA-256、源响应时刻、下载 / 导入时刻和范围证据。

Python 3 标准库通过 ZIP/XML 解析 XLSX，不运行宏，处理 shared strings、inline strings、百分比与日期样式；也支持 CSV。当前导出合同的 16 列如下，未知列仍保留：

| 原表头 | 保存位置 / 统一指标 |
| --- | --- |
| 作品名称 | 原始 cells，参与文案匹配 |
| 发布时间 | 原始 cells，统一为北京时间分钟 |
| 体裁 | 原始 cells |
| 审核状态 | 原始 cells；与网页“已发布”状态分开记录 |
| 播放量 | plays |
| 完播率 | finish_rate |
| 5s完播率 | finish_5s_rate |
| 封面点击率 | cover_ctr |
| 2s跳出率 | bounce_2s_rate |
| 平均播放时长 | avg_play_duration_sec，仅单位明确时换算 |
| 点赞量 | likes |
| 分享量 | shares |
| 评论量 | comments |
| 收藏量 | favorites |
| 主页访问量 | profile_visits |
| 粉丝增量 | follower_gain；不是作者总粉丝数 |

率统一为 0–1，显式百分号除以 100；越界率不猜单位，统一值留 NULL。时长必须有秒 / 毫秒 / 明确时分秒格式，无单位数字不猜秒，原值仍保留。“平均播放占比”不是完播率，也不假设当前 16 列必然提供它。

匹配顺序以 `export.mjs` 为准：

1. 有显式 ID 列时只接受精确字符串 ID，科学计数法或明确错误 ID 不退化为标题猜测。
2. 无 ID 时，发布时间按北京时间（Asia/Shanghai，UTC+8）精确到分钟；无时区时间视为北京时间，ISO 带时区时间转换后匹配。若作品和导出行在该分钟都唯一，直接匹配，不要求标题一致。
3. 同分钟冲突时才用文案消歧：NFKC 归一化、去话题标签、空白、标点和符号；优先与保存的真实 desc 全文一致，其次要求归一化作品标题是导出名称的子串。只有一个候选才接受，不用模糊匹配或行顺序。
4. 多候选记 ambiguous，多行指向同作品时所有相关行记 duplicate，零候选记 unmatched，全部保存且不混合。

导出非空统一值优先，包含真实 0；缺失则回退已确认列表值或 NULL。扩展 JSON 保留完整表头、原值、单位、列表原值和每个指标的最终来源 / 取数时刻；原始列表 `raw_json` 不被导出覆盖。重新导入先恢复列表基线，再按新匹配重建扩展，并将上次导出记录归档到导入历史表。

完整成功要求页面数、主源 total、去重数、快照数、基础完整数一致，导出总行数、接受行数、匹配作品数均等于作品数，重复 / 歧义 / 未匹配为 0。否则保留数据，已有作品时 collect 为 `partial`、退出 2；无作品的普通失败为 failed / 1，登录与锁保留各自专用退出码。导入匹配不足也将目标 run 标记为 partial / 2。

显式复用只接受数据根的 `data/exports/` 真实路径内文件，检查 manifest 与文件哈希，保留原始源时间并记录新的导入时间，不当作重新下载。统计周期未被平台证实就保持未知，不声称近 30 天或全历史。

## 样本验收与报告门禁

`sample` 要求最新 run 完整成功，并从 `DOUYIN_SAMPLE_EVIDENCE_FILE` 加载本机 JSON。下面是纯合成格式示例，使用者应填入自己有来源的实际证据，不得把示例当作验收结果：

```json
{
  "source_type": "用户提供截图转述",
  "source": "本机截图的人工转述与来源说明",
  "source_time": "2026-01-03T12:00:00+08:00",
  "original_image_available": false,
  "aweme_id": "9000000000000000001",
  "title": "合成作品标题",
  "published_minute": "2026-01-02 18:00",
  "page": {
    "plays": "100", "likes": "10", "comments": "2", "shares": "1",
    "favorites": "3", "follower_gain": "1", "cover_ctr": "10.00%"
  }
}
```

当前证据格式是“用户提供截图转述且没有原图”，因此 `original_image_available=false`、验收截图为 null；引用 JSON 不冒充原图。`source_time` 建议使用带时区的 ISO 时间；`published_minute` 必须为北京时间分钟。`page.avg_play_ratio` 可选，仅作上下文。

“新”由该配置的作品 ID、标题和发布时间分钟指定（代码不额外强制它是时间最新的一件），检查播放、赞、评、转、藏、吸粉和封面点击率 7 项。中旧候选必须导出状态公开 / 已发布且播放正数，不能由播放推断公开状态；旧取最早，中取离全目录发布时间跨度中点最近且排除新旧的一件，并列按 ID 排序。候选不足时停止，不放宽标准。

中旧复核是有固定动作范围的文件控制协议：

1. 读取 `logs/sample-v3-run-<run>-<中或旧>-state.json`，其中含 revision、目标归属、候选、可见控件、截图和定位证据。
2. 在同前缀 `-command.json` 写 `{ "revision": 当前版本, "action": "search", "keyword": "目标标题中的关键词" }`。关键词至少两字且来自目标标题；每个目标只允许一次搜索尝试。程序只填“搜索作品”并提交，不触碰编辑功能。
3. 必要时使用 `date` 打开发布日期筛选，`control` 只能引用状态中已观察控件的 index；日期输入只能等于该目标发布日期。`inspect` 刷新状态和 revision，`stop` 中止。旧 revision 会拒绝，操作上限 16 次、每目标等待上限 10 分钟。
4. 确认定位已生效、唯一目标卡片属于该作品且网页状态已发布后，提交 `verify`。默认按目标 DOM 标签读取播放 / 赞 / 评 / 吸粉；可提供 `readings` 字符串对象人工复核，但读数须出现在目标卡片文本中。保存目标截图并与本轮数据库比较。未经定位或读数缺失不能验收。

完整整数精确比较；“万/亿”按显示位数计算截断与四舍五入区间的并集；百分比按所示小数位四舍五入区间比较，上界不含。NULL、短横不当 0。任一指标不符均失败。

`acceptance.mjs` 再次检查三条唯一 ID、类型、来源 / 时间、证据文件存在、归属与数据库指标、比较规则、网页定位生效及读数；成功才写 `data/acceptance.json`，使用通用外部证据合同版本。手写 approved=true 不能绕过。

report 要求最新数据完整，验收记录仍有效且引用已存在的历史 run。历史基线允许用于后续完整采集报告，不代表每六小时重新截图；更换账号、数据或证据会使门禁失败。verify-install 更严格，要求验收 run 等于当前 run，并存在该 run 已生成的报告。初次安装顺序必须是 collect → sample → report → install。

报告包括排行榜、分布、按发布月份的当前快照和零播放附录。按发布月份汇总不是逐月增长；比较历史指标需统计周期与来源可比，同一导出源时刻重复导入不比较。报告概览会包含本地作品的最新快照，当前轮详细分析仅取当前 run；历史已消失作品可能仍在本地累计概览中，跨轮全量分析应自行明确范围。

## SQLite 表结构

`store.mjs` 打开数据库时执行 `schema.sql` 和兼容迁移。WAL、外键开启，busy_timeout=5000；`PRAGMA user_version=1`，部分兼容字段由启动迁移添加，不能只依据版本号判断全部列。

| 表 | 字段与约束 |
| --- | --- |
| works | `aweme_id TEXT PRIMARY KEY`；title NOT NULL，description、published_at、duration_sec、cover_url、work_type、visibility、topic_id、works_dir；first_seen_at / last_seen_at NOT NULL。topic_id / works_dir 供可选内容映射，保存作品不覆盖它们 |
| collect_runs | `id INTEGER PRIMARY KEY`；started_at、finished_at、status（running/success/partial/needs_login/failed）；page_work_count、api_work_count、collected_count、detail_count、error_code；迁移添加 list_metric_count（默认 0）、warnings_json |
| metric_snapshots | `id INTEGER PRIMARY KEY`；run_id → collect_runs、aweme_id → works；collected_at；plays、finish_rate、avg_play_duration_sec、likes、comments、shares、favorites、follower_gain、finish_5s_rate、bounce_2s_rate、cover_ctr、profile_visits 均为可空 REAL；raw_json 为有效 JSON；迁移添加可空有效 JSON extensions_json；UNIQUE(run_id,aweme_id) |
| export_files | `run_id INTEGER PRIMARY KEY` → collect_runs；metadata_json、summary_json NOT NULL，记录文件来源与覆盖 counts / fields |
| export_rows | `id INTEGER PRIMARY KEY`；run_id → collect_runs，aweme_id 可空，status、row_json NOT NULL；保留 matched / ambiguous / unmatched / duplicate 原始行 |
| export_import_history | `id INTEGER PRIMARY KEY`；run_id、imported_at、previous_json NOT NULL；每次覆盖导出前保存旧文件记录及旧行 |

索引为 `snapshots_work_time(aweme_id,collected_at,id)` 与 `snapshots_run(run_id)`。业务 ID 用 TEXT；比率 0–1，时长统一秒，NULL 表示未知或未确认，0 表示实际测得为零。JSON 中保留列单位与来源，不能凭字段名擅自改变口径。

## launchd 调度与跳过逻辑

`install.sh` 自身推导模块路径，不要求仓库位于某个固定位置。先执行离线 verify-install，再用渲染器填充 plist 模板的模块目录、数据根、昵称、Ego 路径、Node 路径与 label；XML 值转义后 plutil 校验，真实文件以 0600 放入 `~/Library/LaunchAgents/<label>.plist`。已有文件 / 标签拒绝覆盖，bootstrap 失败清除本次生成的文件。没有立即 kickstart。

StartInterval=21600（每 6 小时），RunAtLoad=false。`run-scheduled.sh` 只在 collect 退出 0 后运行 report；collect 退出 4 时记录 EGO_PROFILE_LOCKED，wrapper 返回 0 跳过该轮，不 report、不尝试重启浏览器；其他退出码直接传递。模块锁冲突不会被当作忙 Ego 成功跳过。报告自身失败也保持非零。

睡眠或退出用户会话时无法保证定点执行；本轮 Ego 忙不补采。安装时捕获配置，改变目录、昵称、Node 或 Ego 路径后需要用相同 label 卸载并重装。卸载先校验 plist label 并拒绝符号链接，再移除该任务，保留所有数据与登录档。
